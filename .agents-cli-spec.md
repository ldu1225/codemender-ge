# Agent Spec: CodeMender Security Agent for Gemini Enterprise (A2UI v0.9)

## Overview
- **Agent Name**: `codemender_ge`
- **Target Project & Region**: `duleetest` (`us` / `us-central1` Cloud Run Gen2)
- **Gemini Enterprise App ID**: `projects/duleetest/locations/us/collections/default_collection/engines/gemini-enterprise-us-dulee_1774600255749`
- **Core Model**: `gemini-3.8-flash` (configurable via `CODEMENDER_MODEL`, single model across Find, Verify, Fix, and LLM-as-a-Judge)
- **Execution Mode**: Hybrid CodeMender Harness (`cm` CLI binary when available, with built-in ADK Native 3-Stage Find/Verify/Fix Sandbox Harness fallback)
- **Deployment & Registration**: Cloud Run Gen2 container serving A2A Protocol (`--registration-type a2a`) with A2UI v0.9 Extension (`https://a2ui.org/a2a-extension/a2ui/v0.9`) and Dual-Catalog rendering (`codemender_v0_9_catalog` + `BasicCatalog` v0.9).

## Example Use Cases
1. **Direct File Upload & Vulnerability Scan**:
   - **Input**: User uploads a single source file (e.g., `app.py`), multiple source files, or a `.zip` archive in Gemini Enterprise Web UI and asks "이 코드 보안 취약점 진단하고 패치해줘".
   - **Output**: Streaming A2UI v0.9 surfaces (`application/json+a2ui`) showing scan progress, verified CWE/OWASP findings (`MaterialCard`, `MaterialBadge`), side-by-side/unified patch viewer (`CodeDiff`), LLM-as-a-Judge verification score, and `[패치 적용 (Apply Patch)]` / `[전체 패치 적용]` (`MaterialButton`) actions.
2. **Interactive Human-in-the-Loop Patch Application**:
   - **Input**: User clicks `[패치 적용]` (`a2ui_action` event with `vuln_id` and `file_path`).
   - **Output**: Agent applies the verified unified diff to the isolated workspace file, packages the patched source file (and/or patched `.zip`), returns it as a downloadable A2A `FilePart` / ADK Artifact, and updates the A2UI card badge to `PATCH APPLIED ✅`.

## Tools Required
1. `ingest_uploaded_files`: Extracts and validates uploaded `FilePart` / `Blob` / `.zip` archives into `/tmp/cm-workspace-{session_id}/src` with Zip-Slip and size/extension guards.
2. `run_codemender_pipeline`: Orchestrates the 3-stage CodeMender harness (`find` -> `verify` in isolated sandbox -> `fix` + LLM-as-a-Judge) using `gemini-3.8-flash`.
3. `apply_verified_patch`: Handles `a2ui_action` (`apply_patch` / `apply_all_patches`), applies the verified diff, runs post-patch verification, and saves the patched file as an ADK artifact.
4. `render_a2ui_security_report`: Builds and validates A2UI v0.9 JSON payloads (`DataPart` with `mimeType: "application/json+a2ui"`) supporting both the Custom CodeMender Material Catalog (`MaterialCard`, `MaterialBadge`, `CodeDiff`, `MaterialButton`) and A2UI v0.9 BasicCatalog fallback.

## Constraints & Safety Rules
- **False Positive Elimination**: Only vulnerabilities verified in the isolated sandbox (`verified == True`) are presented as actionable patch targets; unverified candidates are filtered out or marked as filtered false positives.
- **Sandbox & Command Execution Isolation**: Never execute user inputs with `shell=True`; enforce strict binary allow-lists, per-session workspace path resolution boundaries (`resolved.startswith(sandbox_dir + os.sep)`), non-executable source file permissions (`0o600`), and execution timeouts.
- **No Raw Text Dump**: When A2UI is active, return structured `application/json+a2ui` `DataPart` payloads rather than raw markdown walls.

## Success Criteria
- Uploaded source files and `.zip` archives in Gemini Enterprise are ingested cleanly without path traversal or memory overflow risks.
- False positive findings are filtered out during the `verify` stage, and true positive findings produce minimal, non-breaking patches (`Unified Diff`).
- All responses validate against the A2UI v0.9 JSON Schema (`a2ui-agent-sdk`) and render interactive cards, badges, diffs, and action buttons.
- Clicking `[패치 적용]` (`a2ui_action`) returns the patched source file artifact cleanly.
